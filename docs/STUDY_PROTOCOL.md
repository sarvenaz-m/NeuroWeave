# Proposed formative study

Status: a plan, not a completed study. The aim is to learn whether the tasks, controls and feedback are understandable and comfortable for the intended users. This protocol does not evaluate rehabilitation efficacy or validate the EEG classifier.

## Questions and recruitment

Ask whether people can understand preview/response states, reach targets comfortably, pause without losing context and choose an appropriate memory length. Ask healthcare professionals whether the interaction tasks address a useful research question for their population.

A proposed first cycle involves 4–6 intended end users and 2–3 relevant healthcare professionals, subject to the host institution’s study approval, recruitment access and accessibility needs. These are planning numbers for qualitative design feedback, not a powered clinical sample or completed recruitment.

## Co-design before measurement

Show sketches and the two playable tasks. Discuss movement constraints, fatigue, visual complexity, wording, pacing, preferred input and what positive feedback should mean. Do not ask participants to interpret synthetic EEG as their own physiology. Record anonymised themes and design decisions; obtain permission before any recording.

The first working version intentionally lets users adjust targets, observe a self-paced cue, pause and accept/decline suggestions. These are hypotheses to test with people, not evidence that co-design already occurred.

## Session plan

| Phase | Proposed activity | Evidence to collect |
| --- | --- | --- |
| Introduction | Explain the prototype, voluntary participation and stopping controls | Understanding and accessibility requirements |
| Familiarisation | Demonstrate one memory and one rule-switching round | Questions, mistaken expectations |
| Two short blocks | Up to eight rounds per block with a break; compare chosen target sizes or cue wording | Completion, observed input errors, exported round outcomes |
| Reflection | Ask about comfort, clarity, agency, frustration and preferred changes | Notes or permitted recordings |
| Practitioner review | Discuss task relevance and appropriate safeguards for future work | Design decisions and unresolved research questions |

Use counterbalanced condition order if comparing two target sizes. Let participants decline a condition or end a block; do not treat stopping as failure. Begin with the browser game only. The EEG demonstration can be shown separately as a software explanation if relevant; no headset data collection is part of this plan.

## Analysis and reporting

Report task completion and errors descriptively, with the input method and level. Response time combines recall, decision and screen action, so it must not be called a pure motor measure. Keep accessibility observations and qualitative themes alongside numeric outcomes. Analyse pauses, requests for help and stopping as design feedback. Do not infer clinical improvement from practice effects or a short repeated session.

Produce an anonymised observation log, a requirements-to-change matrix and a before/after design rationale. Report sample size, missing data, deviations and participant needs. Any later patient/EEG study requires a separately agreed research question, appropriate approvals, consent, data governance, hardware synchronisation and validation design.

## Co-design prompts

- What did you think would happen after “I’m ready”?
- Which part felt difficult to reach or understand?
- What would help you remember the sequence without adding pressure?
- Did you feel in control of the length change and stopping options?
- What should the notebook communicate to a participant and to a researcher?
